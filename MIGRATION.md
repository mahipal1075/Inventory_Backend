- **`npm run migrate`** – performs the actual migration. It is **idempotent** and will abort on any document conflict.

## Conflict Handling
- If a document with the same `_id` already exists **and** its data differs from the backup, the script logs an error, aborts the migration for that collection, and exits with status `conflict`.
- No existing documents are overwritten or deleted.
- The migration can be safely re‑run after resolving conflicts (e.g., by fixing the data manually in MongoDB).

## Rollback Strategy (if needed)
- The script **does not** perform destructive operations (no `drop`, `deleteMany`).
- To revert unintended inserts, manually remove the inserted documents using their `_id` values via MongoDB tools or a temporary script.
- Because the migration is idempotent, re‑running the script after cleanup will only insert missing documents.
